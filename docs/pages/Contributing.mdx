## Start with the repository contract

The repository's
[CONTRIBUTING.md](https://github.com/maksimzayats/specx/blob/main/CONTRIBUTING.md) is the canonical
contributor guide; this page is its docs-site companion. Read the root `AGENTS.md` before editing.
specx publishes two connected products from one repository:
the typed Python guardrail package under `src/specx/` and one optional navigation skill under `skills/specx/`.
Tests and helper scripts live under `tests/` and `scripts/`.

You need uv with a supported Python version and Node.js 20 or newer. Install the locked development
environment, then establish a clean baseline:

```sh
uv sync --locked --all-groups
npm --prefix docs ci
make check
npm --prefix docs run docs:check
```

## Change a skill

Edit only the canonical `skills/specx/` directory. Keep `SKILL.md` concise and
navigation-oriented; put reusable patterns and longer examples in public documentation. Skill frontmatter
contains only `name` and `description`, and its name matches the directory.

After editing, synchronize the tracked local-discovery mirror and validate it:

```sh
make sync-skills
make validate-skills
make list-skills
```

Do not edit `.agents/skills/` by hand. UI metadata in `agents/openai.yaml` must keep its prompt and
description aligned with the canonical skill.

## Change an architecture rule

Preserve the existing semantic rule ID for a compatible refinement. If the rule's contract changes,
introduce a new ID or document the migration. Update the implementation, authored remediation,
detection boundary, focused tests, and authoritative page under `docs/rules/`. If the rule changes
generated-project commands or entrypoints, update the generated agent guidance as well.

```sh
uv run specx rule explain use-cases.return-dtos
make test
make check
```

Changes to the initializer, templates, or generated commands must be tested
by initializing a disposable project. Documentation-only changes are exempt.

## Change these docs

Documentation pages are MDX files under `docs/pages/`. Add each page to
`docs/.storybook/docsNavigation.ts` and the inline Storybook order in
`docs/.storybook/preview.ts`. Every page except Introduction ends with `NextPrev`, and internal
links use Storybook docs paths.

```sh
npm --prefix docs run docs:check
npm --prefix docs run types
npm --prefix docs run build-storybook -- --output-dir storybook-static
npm --prefix docs run docs:check-built
```

Inspect the built site in light and dark themes and at mobile width. Tables and code samples must
scroll locally instead of widening the page. Run `make check` before opening or updating a pull
request.

## Pull request checklist

- Package behavior, public rule pages, and the optional navigation skill agree.
- `make check` and the documentation checks pass.
- Initializer, template, and generated-command changes were exercised in a disposable project.
- No placeholder directories, copied foundation bases, caches, or local environment files are added.
- User-facing prose describes observable behavior and real commands without promotional filler.
