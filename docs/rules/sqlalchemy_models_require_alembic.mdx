## `sqlalchemy.models-require-alembic`

Require Alembic configuration, revisions, commands, and tests for concrete models.

**Status:** Enabled by default.

### Why this exists

A concrete relational model changes the database contract and must be represented by reviewable, testable migrations.

### Failing example

```python
class OrderModel(BaseSQLAlchemyModel):
    pass  # no Alembic revision or migration test
```

### Passing example

```python
class OrderModel(BaseSQLAlchemyModel):
    pass  # Alembic config, revision, Make commands, and integration test exist
```

### Detection notes

When a concrete model exists, parses Alembic configuration and Python imports for Alembic-qualified
configuration and migration calls, an invoked migration entrypoint, an operational revision, and
upgrade-and-drift evidence in the same executable, non-skipped test body. Standard async Alembic
helper and `run_sync` callback chains are followed statically. It also shell-tokenizes `migrate`,
`makemigrations`, and `migration-check` recipes and requires them to invoke Alembic directly;
comments, `echo`, dead branches, swallowed failures, rebound Alembic imports, and uncalled helpers do
not count. Common
direct runners such as `uv run --locked alembic`, `env NAME=value alembic`, and absolute Alembic
executables count. Statically abstract declarative foundation classes do not activate the rule unless
they declare a concrete table mapping.
