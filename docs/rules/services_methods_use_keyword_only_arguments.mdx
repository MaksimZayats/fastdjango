## `services.methods-use-keyword-only-arguments`

Require public service methods to expose explicit keyword-only arguments after self.

**Status:** Enabled by default.

### Why this exists

Keyword-only service APIs make orchestration readable and prevent argument-order mistakes as contracts evolve.

### Failing example

```python
class PriceService(BasePureService):
    def total(self, price: int, quantity: int) -> int:
        return price * quantity
```

### Passing example

```python
class PriceService(BasePureService):
    def total(self, *, price: int, quantity: int) -> int:
        return price * quantity
```

### Detection notes

Checks effective public methods on direct and inherited project pure, read, and effect service
subclasses, including methods declared under class control flow and module-level project functions
attached directly or through exact `staticmethod` and `classmethod` wrappers. Every reachable overload
and runtime implementation is checked. Only the actual instance/class receiver is exempt; static methods
have no implicit receiver. Ordinary positional parameters and `*args` violate the keyword-only contract.
Property getter, setter, and deleter functions are descriptor accessors rather than directly called
service methods, so their runtime-mandated accessor parameters are exempt, including qualified accessor
overrides inherited from an explicitly selected project base or mixin. Abstractness is aggregated over
the effective getter, setter, and deleter components before concrete services are checked. Accessors
supplied through exact `property(...)` positional or `fget`/`fset`/`fdel` arguments receive the same
descriptor exemption. Class-body aliases of `property`, `staticmethod`, and `classmethod` are resolved
in source order; custom shadows and ambiguous branch bindings are not classified as built-ins.
